HIGH CONCURRENCY · Deadlock on unbuffered channel · internal/sync/refund.go:31 · implementation · codex

Issue

done is unbuffered and the only sender runs after the receiver returns on the error path, so a failed sync blocks the worker forever.

done := make(chan struct{})
if err != nil {
	return err // nobody ever drains done
}
done <- struct{}{}

Suggested fix

Buffer the channel (make(chan struct{}, 1)) or select with a context cancel.

Why it matters / details

  • A single failed sync hangs the worker forever.
  • ELI5: A worker waits to hand off a signal that nobody is listening for on the error path.
MEDIUM LAYERING · Handler reaches into storage · internal/sync/handler.go:18 · architecture · opus

Issue

The HTTP handler imports the storage package directly instead of going through the service layer, coupling transport to persistence.

import "wallet-svc/internal/storage"

Suggested fix

Inject a service interface and call that; keep storage behind it.

Why it matters / details

  • Transport and persistence get tangled, making both harder to change/test.
  • ELI5: The web handler talks straight to the database package.
